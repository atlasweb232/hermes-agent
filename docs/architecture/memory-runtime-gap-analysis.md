## 3. The redaction reinvention (key finding for Gap 4)
THREE redaction implementations exist:
1. `agent/redact.py::redact_sensitive_text(text, *, force, code_file)` — canonical, mature, shared with upstream (but 252 lines behind upstream's version).
2. `hermes_cli/runtime_lesson_capture.py::redact_sensitive_text(text, *, max_chars=2000)` — fork-local duplicate, weaker.

## 5d. Phase 3 — dedup-enforcing curation (IN PROGRESS, 2026-05-30)
- **Diagnosis:** `classify_dedupe` already *detects* exact/near/conflict/supersedes relationships, but `persist_global_lesson` does `INSERT OR REPLACE` keyed only on the content-hash `id`, so only *exact* collisions collapse. Near-duplicates rediscovered by different tenants landed as parallel rows, and concurrent promotion races (read-pool → classify → write, no serialization) could duplicate global lessons.
- **Built (merge + corroboration + quorum):** `merge_or_persist_global_lesson` (`hermes_cli/global_memory.py`) is the curation write path — runs `classify_dedupe` against the non-retired pool and acts on the verdict: `exact/near/same_topic/same_evidence/supersedes` → **merge into the canonical lesson**; `conflict` → quarantine the incoming claim with `conflicts_with` provenance; else → create. `merge_global_lesson_records` accumulates cross-tenant corroboration (`approval_provenance.corroborations` + `corroboration_count`), unions evidence/citation refs, sums reuse_stats, and bounds confidence. `lesson_corroboration_count` (distinct tenants) + `lesson_meets_quorum(min_distinct_tenants, require_held_out)` are the **quorum gate** — and `require_held_out` ties straight into the held-out verification work (§5c): cross-tenant promotion can demand a worker-unseen proof.
- **Anti-poisoning property (deliberate):** a merge NEVER rewrites the canonical claim text or signatures — a higher-confidence "supersedes" near-dup is only *recorded for review* (`supersede_candidates`), never applied. Otherwise a crafted high-confidence near-duplicate would be a content-poisoning vector. Independent rediscovery becomes a quorum signal; corroboration from the same tenant does not inflate quorum. Tests: `tests/hermes_cli/test_global_curation.py` (7) incl. the text-preservation and same-tenant-no-inflation cases. **181/181 pass** (3 skipped = live-PG).
- **Single-consumer curator (DONE, 2026-05-30):** `hermes_cli/global_curator.py` closes the TOCTOU race architecturally. Tenants no longer write the global pool directly — `publish_global_lesson_proposal` publishes an idempotent proposal (`event_key` = tenant+text+evidence hash) to the dedupe topic; `run_global_curator_once`/`run_global_curator_loop` is the **single ordered consumer** that leases events and applies `merge_or_persist_global_lesson` **serially**. One writer ⇒ read-then-write is serialized ⇒ no race. The durable bus (`learning_bus`) supplies ordering, at-least-once delivery, idempotent dedup, leasing, retry and dead-lettering. Failures are left unacked (lease-expiry retry → eventual dead-letter via max_attempts), so a poison-pill can't wedge the topic. Each drained lesson is checked against the quorum gate and surfaced in `CurationRunResult`. Scaling: partition the bus by dedup-cluster key (failure_signature/simhash bucket) so near-dups of a cluster hit the same consumer — serialized within a cluster, parallel across. Tests: `tests/hermes_cli/test_global_curator.py` (5) incl. not-written-until-drained, idempotent redelivery, cross-tenant serial merge, ack-no-reprocess. **149/149 pass** (3 skipped = live-PG).
- **Supervisor→global promotion + quorum-gated lifecycle (DONE, 2026-05-30):** `promote_candidate_to_global_pool` (`global_curator.py`) is the candidate→global link. It does NOT write the pool — it builds a proposal from an approved meta-candidate and `publish_global_lesson_proposal`s it to the curator. Gated: the candidate must be `approved`/`applied` AND carry passing verification; for global scope, **held-out verification is required by default** (the teacher-independence rule, `require_held_out_for_global`). The proposal enters **quarantined** — NOT in the usable set `{approved, canonical, applied}`, so it is never retrieved. The curator flips `quarantined → canonical` (usable) **only once distinct-tenant quorum is met** (`promote_on_quorum`, default on). Net effect — the concrete poisoning defense: **one tenant alone can never make a global lesson live; it takes N distinct tenants (or held-out corroboration) to promote a quarantined lesson to usable.** Tests: `tests/hermes_cli/test_global_promotion.py` (5) — unverified blocked, non-held-out blocked under the global rule, single-tenant stays quarantined/unusable, two-tenant corroboration → canonical/usable, unapproved blocked. **134/134 pass** (3 skipped = live-PG).
- **Still open in Phase 3:** (1) **canary** stage between quarantine and canonical (single-tenant shadow read before full activation) — currently quarantine→canonical is one hop on quorum. (2) signed provenance per contributing tenant (shares the Phase 4 signing primitive). (3) adversarial corpus CI gate + drift/contradiction hygiene (auto-retire on contradiction). (4) wire `promote_candidate_to_global_pool` into the operator/curator CLI + sidecar schedule (function exists; not yet exposed as a command).
